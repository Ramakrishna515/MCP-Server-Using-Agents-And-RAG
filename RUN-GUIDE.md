## Prerequisites

| Tool | Why | Check with |
| --- | --- | --- |
| **Node.js** v18+ | Runs the server and build tools | `node --version` |
| **npm** (comes with Node) | Installs dependencies | `npm --version` |
| **Git** | Clones/versions the repo | `git --version` |

No API key is required to **build, run the server, or run the test**. Keys are only
needed when you actually call an LLM (client / web / RAG answer).

## Folder Structure

| Path | What it is | In git? |
| --- | --- | --- |
| `src/*.ts` | TypeScript source (the code you edit) | ✅ |
| `dist/*.js` | Compiled output (auto-generated by build) | ❌ (gitignored) |
| `node_modules/` | Downloaded dependencies (auto-generated) | ❌ (gitignored) |
| `data/notes.json` | Your saved notes | ❌ (gitignored) |
| `data/index.json` | Vector index for RAG | ✅ |
| `tools/*.md` | Per-agent tool documentation | ✅ |
| `*.md` | Guides | ✅ |
| `Jenkinsfile` | CI pipeline | ✅ |

> **Never edit `dist/` or `node_modules/`** — delete them anytime; rebuild/reinstall regenerates them.

## 1. Setup

```bash
# 1. Install dependencies
npm install          # or: npm ci  (uses package-lock.json, exact versions)

# 2. Provide API keys (only needed for LLM calls / web search)
cp .env.example .env # if .env.example exists, then edit .env with real keys
```

## 2. Environment Variables (.env)

| Variable | Purpose |
| --- | --- |
| `XAI_API_KEY` | Grok (free) — used by the chat `client` |
| `OPENAI_API_KEY` | Optional OpenAI provider |
| `ANTHROPIC_API_KEY` | Optional Claude provider |
| `GEMINI_API_KEY` | Gemini provider — used by RAG answers |
| `TINYFISH_API_KEY` | Free web-search API — used by `search_web` tool |
| `PORT` | Web portal port (default `3000`) |

> ⚠️ **`.env` contains secrets — it is gitignored. Never commit it or paste its keys.**
> The example showed in chat is a real-looking key; treat all keys as secret.

## 3. Build

```bash
npm run build
```

What it does: runs `tsc`, compiling every `src/*.ts` into `dist/*.js`.

**Expected output:**
```
> build-mcp-server@1.0.0 build
> tsc
```
(No errors = success. The `dist/` folder is created/updated.)

---

## 4. Run the Server

```bash
npm run server
```

What it does: `node dist/server.js` — starts the MCP server on **stdio** and waits
for a client to connect.

**Expected output:**
```
Notes MCP Server running on stdio
```

> The server keeps running (waits for MCP clients). Press `Ctrl+C` to stop.
> It needs a client to talk to — it prints no further output by itself.

## 5. Run the Automated Test

```bash

```

What it does: builds, then runs `dist/test.js` — a real MCP client that spawns the

**Expected output (example):**

## 6. Run the MCP Client

```bash
npm run client
```

What it does: `node dist/client.js` — connects to the server and sends a chat
message **through an LLM (Grok)**. Requires `XAI_API_KEY` in `.env`.

```bash
# Without a key you'll see:
Missing XAI_API_KEY env var. Get a free key from console.x.ai and:
  export XAI_API_KEY=xai-...
```

## 7. Run the Web Portal

```bash
npm run web
```

What it does: builds and starts the HTTP server (also loads `.env`).
Open **http://localhost:3000** in your browser.
Requires `GEMINI_API_KEY` for chat answers and `TINYFISH_API_KEY` for web search.
Port comes from the `PORT` env var.

## 9. Run in Jenkins (CI) — End to End

This section explains everything: what Jenkins does, the prerequisites, creating the
job, what each pipeline stage runs, how to read results, and how to fix failures.

### 9.1 What Jenkins does here

Jenkins is a CI server. You give it a repo and a recipe (the `Jenkinsfile`);
every time you tell it to build (or push), it automates:

```
checkout code → npm ci → npm run build → npm run test
              → server smoke test → web smoke test → clean workspace
```

That is exactly the pipeline defined in `Jenkinsfile` at the repo root.

### 9.2 Prerequisites on the Jenkins machine

| Requirement | Why |
| --- | --- |
| **Jenkins** installed | The CI server itself |
| **Java 17+** | Jenkins requires it to run |
| **Docker** | Only because the pipeline uses `agent { docker { image 'node:22' } }` — it pulls a Node 22 container so Node isn't needed on the host |
| **Git** | For `checkout scm` |

> No Docker? Change `agent { docker { image 'node:22' } }` (line 2 of `Jenkinsfile`)
> to `agent any`, then install Node.js 18+ directly on the Jenkins agent.

Recommended plugins (from the default install most ship with): **Pipeline
(workflow-aggregator)**, **Git**, **Timestamper**, **AnsiColor**, and
**Workspace Cleanup (`ws-cleanup`)** — the last one is required because the
`Jenkinsfile` calls `cleanWs()`, and **Docker Pipeline (`docker-workflow`)** is
required for the `node:22` Docker agent.

### 9.3 Create the Jenkins job (one-time setup)

1. Open Jenkins → **New Item** (top-left).
2. Enter a name, e.g. `build-mcp-server`, choose **Pipeline**, click **OK**.
3. Scroll to the **Pipeline** section at the bottom:
   - **Definition:** `Pipeline script from SCM`
   - **SCM:** `Git`
   - **Repository URL:** your repo, e.g. `https://github.com/you/buildMCPserver.git`
   - **Branches to build:** `*/testing` (your current branch)
   - **Script Path:** `Jenkinsfile`
4. Click **Save**.

That is all the config. Everything else comes from the `Jenkinsfile`.

### 9.4 What happens when you click **Build Now**

Matching the `Jenkinsfile` stage by stage:

**Stage: Checkout**
```
[Pipeline] { (Checkout)
git fetch ...
```
Jenkins creates a clean workspace, clones the repo, and checks out your branch.

**Stage: Environment**
```
node --version   →  v22.x.x
npm --version    →  10.x.x
```
Runs inside the `node:22` Docker container — the container's Node, not your laptop's.

**Stage: Install dependencies**
```
npm ci
added 98 packages ... found 0 vulnerabilities
```
`npm ci` wipes `node_modules` and installs **exact** versions from
`package-lock.json` (frozen — reproducible builds).

**Stage: Build**
```
npm run build
> tsc
```
`tsc` compiles every `src/*.ts` into `dist/*.js`. No errors printed = success.

**Stage: Test**
```
npm run test
> node dist/test.js
Connected. Listing tools...
Tools: search_web (...), add_note (...), ...
Adding a note...
Listing notes...
Test passed.
```
This is the real end-to-end verification: it spawns the server, connects a real
MCP client, lists tools, adds notes, and lists them back. Last line `Test passed.`
= pipeline is green.

**Post: cleanup**
```
[Pipeline] { (cleanWs)
```
`cleanWs()` deletes the whole workspace, so every build starts from scratch
(notes from the test are discarded — expected).

### 9.5 Reading the results

- **Blue ball = success**, **red = failure**.
- Click a build number → **Console Output** → read each `[Pipeline] { (Stage)` block.
- The **Stage View** tab shows one row per stage with its own status/time; the
  failing stage is highlighted red.

### 9.6 If a stage fails — diagnose it

| Fails at | Look for in console | Real cause / fix |
| --- | --- | --- |
| Checkout | `Could not fetch ... authentication` | wrong repo URL or no access |
| Install | `npm ci ... EINTEGRITY` | lockfile drift — push a fresh `package-lock.json` |
| Build | `error TS...` | a TypeScript error in `src/` |
| Test | `Error: Cannot find module` | missing/rebuild issue — rerun `npm ci && npm run build && npm run test` locally |
| Any | `Agent ... offline` / `docker: not found` | Docker not running on the agent |

Every error prints the failing command — reproducing it in your terminal
(the three commands in the table) usually shows the same error, so you can fix it locally.

### 9.7 Running it again / automatically

- **Manual:** click **Build Now** — the full pipeline runs again.
- **On every push:** enable the GitHub trigger (or **Poll SCM**) in job config.
- Pipeline keeps only the last 10 builds (`buildDiscarder` in `Jenkinsfile`).

**Example console tail on success:**
```
[Pipeline] { (Build)
> npm run build
[Pipeline] { (Test)
TS> node dist/test.js
Test passed.
[Finished] SUCCESS (1m 2s)
```

### 9.8 Verified end to end (ran locally, real output)

The exact flow below was executed on a local Jenkins (Docker) and the pipeline
finished **SUCCESS** in ~14 s with `Test passed.` — this is proof the whole chain
works, not just the guide text.

1. Started Jenkins in Docker:
   ```bash
   docker run -d --name jenkins-local -p 8090:8080 \
     -v /var/run/docker.sock:/var/run/docker.sock \
     -e JENKINS_OPTS="-Djenkins.install.runSetupWizard=false" \
     jenkins/jenkins:lts-jdk21
   ```
2. Installed the pipeline plugins:
   ```bash
   docker exec jenkins-local jenkins-plugin-cli --plugins \
     git workflow-aggregator timestamper ansicolor docker-workflow ws-cleanup
   docker restart jenkins-local
   ```
3. Created job `build-mcp-server` via API: **Pipeline script from SCM**, repo
   `https://github.com/Ramakrishna515/MCP-Server-Using-Agents-And-RAG.git`,
   branch `*/Testing`, script path `Jenkinsfile`.
4. Clicked **Build**. Console confirms each step really ran:
   ```
   Obtained Jenkinsfile from git https://github.com/Ramakrishna515/...git
   Checking out Revision fd4f54f... (refs/remotes/origin/Testing)
   + docker inspect -f . node:22
   $ docker run -t -d -u 1000:1000 ... node:22 cat
   [Pipeline] { (Install dependencies)
   [Pipeline] { (Build)
   [Pipeline] { (Test)
   Notes MCP Server running on stdio
   Test passed.
   Finished: SUCCESS (13.9 s)
   ```

**Two gotchas discovered and how to avoid them:**
- `docker: not found` → the Jenkins image has **no docker CLI**. Install it inside
  the container (`docker exec -u 0 jenkins-local sh -c 'apt-get install -y docker.io'`)
  so the `node:22` agent can be spawned; without Docker you must use `agent any`.
- `No such DSL method 'cleanWs'` → `cleanWs` needs the **Workspace Cleanup plugin**
  (`ws-cleanup`). Install it or remove the `cleanWs()` line.
- Jenkins jobs POST via API need the CSRF **crumb** (session-bound cookie) or calls
  return `403`.

That Jenkins instance is shared for local testing at `http://localhost:8090`; to stop
it later: `docker rm -f jenkins-local`.

## Troubleshooting

| Symptom | Cause | Fix |
| --- | --- | --- |
| `npm: command not found` | Node not installed | Install Node.js v18+ |
| `Cannot find module './server.js'` | `dist/` missing | `npm run build` |
| `Cannot find module '@modelcontextprotocol/sdk'` | deps missing | `npm install` |
| `Missing XAI_API_KEY env var` | client needs a key | add key to `.env` |
| `❌ TINYFISH_API_KEY not set` | search tool needs key | add key to `.env` |
| Test fails with hooks/port errors | stale process | restart terminal, delete `data/notes.json` |
| Jenkins: `Agent is offline or cannot connect` | docker image pull issue | ensure Docker running on agent |
